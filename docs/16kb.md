# 16 KB page alignment

Builds apply `io.github.supermonster003.autojs6-native-alignment:1.9.7`. Every assembled APK
is checked and reports are written to `app/build/reports/native-alignment/`.
Use `:app:verifyNativePageAlignment` to recheck existing artifacts.

The app has no native code of its own. The only native library is `libandroidx.graphics.path.so`
from Compose `ui-graphics`, used by the release history page, so the plugin runs with
`expectNoNativeLibraries=false`. It ships on 4 ABIs (`arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`),
stored uncompressed and 16 KB aligned. `verifyReleaseNativeLibraries` fails the release collection
on any other, compressed or missing library. The plugin writes the Manifest meta-data
`org.autojs.plugin.contract.SUPPORTED_ABIS` for the host and the official index, and the Manifest
declares `org.autojs.plugin.contract.NATIVE_PAGE_ALIGNMENT = 16384`.

Every native dependency or toolchain upgrade must pass the gate again. Static alignment
does not prove runtime behavior: test on a device reporting `getconf PAGE_SIZE = 16384`
with compatibility mode disabled. No `android:pageSizeCompat` override is permitted.

中文: 插件自身没有原生代码, 唯一的原生库是发行历史页所用 Compose `ui-graphics` 的
`libandroidx.graphics.path.so` (4 个 ABI, 不压缩存储, 16 KB 对齐), 因此使用
`expectNoNativeLibraries=false`; `verifyReleaseNativeLibraries` 在出现其他原生库, 压缩存储或缺失时
让发布收集失败. 构建门禁检查全部产物并输出 JSON 报告. 原生依赖或工具链升级后必须重新校验,
且需在页大小为 16384 的设备上关闭兼容模式后执行运行时验证.
